= Exercises
:toc: left
:toclevels: 3
:sectanchors:
:source-highlighter: rouge

Exercises for WideWorldImporters: business questions that the sales, purchasing, warehouse and finance people of a
wholesale novelty-goods importer would ask, each answered with a query. Every problem is stated as a request, followed
by its solutions. The `sql` blocks are Transact-SQL against the installed database (see the project's
link:../../../../README.md[README.md]); a parameter is a local variable, `DECLARE`d right above the query. The `jpaql` blocks are
Jakarta Persistence 3.2 query language against this module's entities, with named parameters of the same names.

The SQL is in `src/test/sql-exercises/_<Schema>/<NN>_<level>.sql`, a file per schema and level. The query language and Criteria API
solutions are the nested classes of the `_<Schema>_Exercises_<NN>_<Level>_PersistenceIT` classes, in
`src/test/java-exercises`, a nested class per exercise, which assert
the rows the SQL returns.

The problems are grouped by the schema of the table they are about; a problem which joins another schema's tables
stays with the one it asks about. Each section goes from Basic (`B`) through Intermediate (`I`) to Advanced (`A`). An
id is `WWI_<SCHEMA>_<TIER>_<NN>`, numbered within its schema and tier, and `EXERCISES.yaml` registers every one; an
id is permanent: it is never renumbered or reused.

A few things about the mappings shape the solutions:

* A foreign key is mapped twice: as an association on the entity, and as a read-only basic attribute on its mapped
  superclass. `Invoice` has `customer`, and `customerId` from `MappedInvoice`; a query may use either.
* A computed column (`IsFinalized`, `ConfirmedDeliveryTime`, `ConfirmedReceivedBy`, `Tags`, `SearchDetails`, ...) is a
  read-only attribute, and a query reads it like any other.
* What the query language has no word for is SQL only: the JSON functions (`JSON_VALUE`), the methods of `geography`
  (`STDistance`), window functions (`RANK() OVER`) and the temporal clauses (`FOR SYSTEM_TIME`). From Jakarta
  Persistence such SQL is sent as a native query; `WWI_SALES_A_02` shows one.
* Grouping is by an entity's identifier and the columns selected, not by the entity: `Customer` and `Supplier` have
  `geography` columns, which SQL Server can not group by.

==== WWI_APPLICATION_B_02: The sales territories of a country

The sales manager sizes the sales territories of a country: for each territory, the number of states or provinces and their total population, the most populous first, a tie by territory.

[source,sql]
----
DECLARE @countryName nvarchar(60) = N'United States';
SELECT sp.SalesTerritory, COUNT(*) AS StateProvinces, SUM(sp.LatestRecordedPopulation) AS Population
FROM Application.StateProvinces sp
         JOIN Application.Countries c ON c.CountryID = sp.CountryID
WHERE c.CountryName = @countryName
GROUP BY sp.SalesTerritory
ORDER BY Population DESC, sp.SalesTerritory

[[WWI_APPLICATION_I_02]]
==== WWI_APPLICATION_I_02: The employees by title, from the CustomFields JSON

Human resources counts the employees by title, with the earliest hire date of each title. The title and the hire date
are in the CustomFields JSON document; JSON_VALUE is SQL only.

[source,sql]
----
SELECT JSON_VALUE(CustomFields, '$.Title')                       AS Title,
       COUNT(*)                                                  AS Employees,
       MIN(CAST(JSON_VALUE(CustomFields, '$.HireDate') AS date)) AS FirstHired
FROM Application.People
WHERE IsEmployee = 1
GROUP BY JSON_VALUE(CustomFields, '$.Title')
ORDER BY Employees DESC, Title
----

[[WWI_APPLICATION_A_01]]
==== WWI_APPLICATION_A_01: The five cities nearest to a city

Find the five other cities nearest to a given city, with their state code and the distance in kilometres; a city whose distance cannot be computed is left out, and `CityID` breaks a tie.

[source,sql]
----
DECLARE @cityId int = 30378; -- San Francisco
SELECT TOP (5) c.CityID, c.CityName, sp.StateProvinceCode, CAST(c.Location.STDistance(o.Location) / 1000 AS decimal(10, 1)) AS Kilometres
FROM Application.Cities c
         JOIN Application.StateProvinces sp ON sp.StateProvinceID = c.StateProvinceID
         JOIN Application.Cities o ON o.CityID = @cityId
WHERE c.CityID <> o.CityID
  AND c.Location.STDistance(o.Location) IS NOT NULL
ORDER BY c.Location.STDistance(o.Location), c.CityID
----

=== Advanced

[[WWI_PURCHASING_A_01]]
==== WWI_PURCHASING_A_01: The suppliers' late deliveries

The buyer rates the suppliers on delivery: for each supplier, the finalized purchase orders received in full, how many of them arrived after the expected delivery date, and the average days late; the most late orders first, a tie by name.

[source,sql]
----
WITH received AS (SELECT po.PurchaseOrderID, po.SupplierID, po.ExpectedDeliveryDate, MAX(pol.LastReceiptDate) AS ReceivedDate
                  FROM Purchasing.PurchaseOrders po
                           JOIN Purchasing.PurchaseOrderLines pol ON pol.PurchaseOrderID = po.PurchaseOrderID
                  WHERE po.IsOrderFinalized = 1
                    AND po.ExpectedDeliveryDate IS NOT NULL
                  GROUP BY po.PurchaseOrderID, po.SupplierID, po.ExpectedDeliveryDate
                  HAVING COUNT(pol.LastReceiptDate) = COUNT(*))
SELECT s.SupplierName,
       COUNT(*)                                                                                AS Orders,
       SUM(CASE WHEN r.ReceivedDate > r.ExpectedDeliveryDate THEN 1 ELSE 0 END)                AS Late,
       CAST(AVG(CAST(DATEDIFF(day, r.ExpectedDeliveryDate, r.ReceivedDate) AS decimal(10, 1))) AS decimal(10, 1)) AS AverageDaysLate
FROM received r
         JOIN Purchasing.Suppliers s ON s.SupplierID = r.SupplierID
GROUP BY s.SupplierID, s.SupplierName
ORDER BY Late DESC, s.SupplierName
----

[[WWI_PURCHASING_A_02]]
==== WWI_PURCHASING_A_02: Each supplier's three most overdue purchase orders

For each supplier, up to three purchase orders not finalized whose expected delivery date is before a cutoff and which have a line not finalized and short-received, the earliest expected first; `PurchaseOrderID` breaks a tie.

[source,sql]
----
DECLARE @asOf date = '2016-06-01';
WITH overdue AS (SELECT po.PurchaseOrderID,
                        po.SupplierID,
                        po.ExpectedDeliveryDate,
                        ROW_NUMBER() OVER (PARTITION BY po.SupplierID ORDER BY po.ExpectedDeliveryDate, po.PurchaseOrderID) AS Position
                 FROM Purchasing.PurchaseOrders po
                 WHERE po.IsOrderFinalized = 0
                   AND po.ExpectedDeliveryDate < @asOf
                   AND EXISTS (SELECT 1
                               FROM Purchasing.PurchaseOrderLines pol
                               WHERE pol.PurchaseOrderID = po.PurchaseOrderID
                                 AND pol.IsOrderLineFinalized = 0
                                 AND pol.ReceivedOuters < pol.OrderedOuters))
SELECT s.SupplierID, s.SupplierName, o.PurchaseOrderID, o.ExpectedDeliveryDate
FROM overdue o
         JOIN Purchasing.Suppliers s ON s.SupplierID = o.SupplierID
WHERE o.Position <= 3
ORDER BY s.SupplierName, o.Position
----

// NOT YET RUN

[[WWI_SALES_I_04]]
==== WWI_SALES_I_04: The history of a customer's credit limit

Accounts receivable wants the history of a customer's credit limit: each limit it has had, from when it was set, the oldest first.
`FOR SYSTEM_TIME ALL` reads the current row and the history together, and `LAG` keeps the versions whose limit changed, NULLs compared as equal; this is SQL only.

[source,sql]
----
DECLARE @customerId int = 890;
WITH versions AS (SELECT CustomerID,
                         CreditLimit,
                         ValidFrom,
                         LAG(CreditLimit) OVER (ORDER BY ValidFrom) AS PreviousLimit,
                         ROW_NUMBER() OVER (ORDER BY ValidFrom)     AS Version
                  FROM Sales.Customers FOR SYSTEM_TIME ALL
                  WHERE CustomerID = @customerId)
SELECT CustomerID, CreditLimit, ValidFrom AS SetFrom
FROM versions
WHERE Version = 1
   OR NOT EXISTS (SELECT CreditLimit
                  INTERSECT
                  SELECT PreviousLimit)
ORDER BY ValidFrom
----

=== Advanced

[[WWI_SALES_A_01]]
==== WWI_SALES_A_01: The top three salespeople of each year

The sales manager ranks the salespeople of each year by the invoiced extended price and wants the top three places of each year, all of those tied for a place included, ordered by `PersonID` within a place.
`RANK() OVER (...)`, a window function, is SQL only; a tie for third can return more than three rows.

[source,sql]
----
WITH yearly AS (SELECT YEAR(i.InvoiceDate) AS SalesYear, i.SalespersonPersonID, SUM(il.ExtendedPrice) AS Revenue
                FROM Sales.Invoices i
                         JOIN Sales.InvoiceLines il ON il.InvoiceID = i.InvoiceID
                GROUP BY YEAR(i.InvoiceDate), i.SalespersonPersonID),
     ranked AS (SELECT y.*, RANK() OVER (PARTITION BY y.SalesYear ORDER BY y.Revenue DESC) AS SalesRank
                FROM yearly y)
SELECT r.SalesYear, r.SalesRank, p.PersonID, p.FullName, r.Revenue
FROM ranked r
         JOIN Application.People p ON p.PersonID = r.SalespersonPersonID
WHERE r.SalesRank <= 3
ORDER BY r.SalesYear, r.SalesRank, p.PersonID
----

[[WWI_SALES_A_02]]
==== WWI_SALES_A_02: The customers whose credit limit changed since a moment, by a native query

Accounts receivable wants the customers whose credit limit is not what it was at a past moment, a limit set or removed since then included, with the limit then and now.
`NOT EXISTS (SELECT then INTERSECT SELECT now)` compares the two with NULLs as equal, which `<>` does not.

[source,sql]
----
DECLARE @asOf datetime2 = '2015-01-01';
SELECT c.CustomerID, c.CustomerName, h.CreditLimit AS CreditLimitThen, c.CreditLimit AS CreditLimitNow
FROM Sales.Customers c
         JOIN Sales.Customers FOR SYSTEM_TIME AS OF @asOf h ON h.CustomerID = c.CustomerID
WHERE NOT EXISTS (SELECT h.CreditLimit
                  INTERSECT
                  SELECT c.CreditLimit)
ORDER BY c.CustomerID
----

[[WWI_WAREHOUSE_I_03]]
==== WWI_WAREHOUSE_I_03: The movements of a stock item in a year, by transaction type

The warehouse manager wants the movements of a stock item in a year: for each transaction type, the number of transactions and the net quantity, by type name.

[source,sql]
----
DECLARE @stockItemId int = 1, @from datetime2 = '2015-01-01', @to datetime2 = '2016-01-01';
SELECT tt.TransactionTypeName, COUNT(*) AS Transactions, SUM(sit.Quantity) AS Quantity
FROM Warehouse.StockItemTransactions sit
         JOIN Application.TransactionTypes tt ON tt.TransactionTypeID = sit.TransactionTypeID
WHERE sit.StockItemID = @stockItemId
  AND sit.TransactionOccurredWhen >= @from
  AND sit.TransactionOccurredWhen < @to
GROUP BY tt.TransactionTypeID, tt.TransactionTypeName
ORDER BY tt.TransactionTypeName

[[WWI_WAREHOUSE_I_04]]
==== WWI_WAREHOUSE_I_04: Incoming and outgoing stock movements

For each stock item with movements in a period, the quantity in, the quantity out as a positive amount, and the net movement, by item name.

[source,sql]
----
DECLARE @from datetime2 = '2016-05-01', @to datetime2 = '2016-06-01';
SELECT si.StockItemID,
       si.StockItemName,
       SUM(CASE WHEN st.Quantity > 0 THEN st.Quantity ELSE 0 END)  AS Incoming,
       SUM(CASE WHEN st.Quantity < 0 THEN -st.Quantity ELSE 0 END) AS Outgoing,
       SUM(st.Quantity)                                             AS NetMovement
FROM Warehouse.StockItemTransactions st
         JOIN Warehouse.StockItems si ON si.StockItemID = st.StockItemID
WHERE st.TransactionOccurredWhen >= @from
  AND st.TransactionOccurredWhen < @to
GROUP BY si.StockItemID, si.StockItemName
ORDER BY si.StockItemName
----

[[WWI_WAREHOUSE_A_01]]
==== WWI_WAREHOUSE_A_01: The cold-room readings of a period, from the history

Quality control checks the cold rooms over a period: for each sensor, the number of readings recorded in the period and the lowest, highest and average temperature.
Each reading is a version of a row of a system-versioned table, so the query reads them all with `FOR SYSTEM_TIME ALL` and keeps those recorded in the period by `RecordedWhen`; `FROM ... TO` would also return the reading still in force when the period began. This is SQL only.

[source,sql]
----
DECLARE @from datetime2 = '2016-05-01', @to datetime2 = '2016-05-02';
SELECT ColdRoomSensorNumber,
       COUNT(*)                                 AS Readings,
       MIN(Temperature)                         AS Lowest,
       MAX(Temperature)                         AS Highest,
       CAST(AVG(Temperature) AS decimal(10, 2)) AS Average
FROM Warehouse.ColdRoomTemperatures FOR SYSTEM_TIME ALL
WHERE RecordedWhen >= @from
  AND RecordedWhen < @to
GROUP BY ColdRoomSensorNumber
ORDER BY ColdRoomSensorNumber
----
