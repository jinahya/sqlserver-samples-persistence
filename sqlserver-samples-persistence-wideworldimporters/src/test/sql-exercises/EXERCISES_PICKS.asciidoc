Exercises for WideWorldImporters: business questions that the sales, purchasing, warehouse and finance people of a
wholesale novelty-goods importer would ask, each answered with a query. Every problem is stated as a request, followed
by its solutions. The `sql` blocks are Transact-SQL against the installed database (see the project's
link:../../../../README.md[README.md]); a parameter is a local variable, `DECLARE`d right above the query. The `jpaql` blocks are
Jakarta Persistence 3.2 query language against this module's entities, with named parameters of the same names.

The SQL is in `src/test/sql-exercises/_<Schema>/<NN>_<level>.sql`, a file per schema and level. The query language and Criteria API
solutions are in `src/test/java-exercises`, a class per exercise, `wwi.<schema>.<ID>_PersistenceIT`; a picked one
asserts the rows the SQL returns.

The problems are grouped by the schema of the table they are about; a problem which joins another schema's tables
stays with the one it asks about. Each section goes from Basic (`B`) through Intermediate (`I`) to Advanced (`A`). An
id is `WWI_<SCHEMA>_<TIER>_<NN>`, numbered within its schema and tier, and `EXERCISES.yaml` registers every one; an
id is permanent: it is never renumbered or reused.

A few things about the mappings shape the solutions:

* A foreign key is mapped twice: as an association on the entity, and as a read-only basic attribute on its mapped
  superclass. `Invoice` has `customer`, and `customerId` from `MappedInvoice`; a query may use either.
* A computed column (`IsFinalized`, `ConfirmedDeliveryTime`, `ConfirmedReceivedBy`, `Tags`, `SearchDetails`, ...) is a
  read-only attribute, and a query reads it like any other.
* What the query language has no word for is SQL only: the JSON functions (`JSON_VALUE`), the methods of `geography`
  (`STDistance`), window functions (`RANK() OVER`) and the temporal clauses (`FOR SYSTEM_TIME`). From Jakarta
  Persistence such SQL is sent as a native query; `WWI_SALES_A_02` shows one.
* Grouping is by an entity's identifier and the columns selected, not by the entity: `Customer` and `Supplier` have
  `geography` columns, which SQL Server can not group by.

==== WWI_SALES_A_02: The customers whose credit limit changed since a moment, by a native query

Accounts receivable wants the customers whose credit limit is not what it was at a past moment, a limit set or removed since then included, with the limit then and now.
`NOT EXISTS (SELECT then INTERSECT SELECT now)` compares the two with NULLs as equal, which `<>` does not.

[source,sql]
----
DECLARE @asOf datetime2 = '2015-01-01';
SELECT c.CustomerID, c.CustomerName, h.CreditLimit AS CreditLimitThen, c.CreditLimit AS CreditLimitNow
FROM Sales.Customers c
         JOIN Sales.Customers FOR SYSTEM_TIME AS OF @asOf h ON h.CustomerID = c.CustomerID
WHERE NOT EXISTS (SELECT h.CreditLimit
                  INTERSECT
                  SELECT c.CreditLimit)
ORDER BY c.CustomerID
----

SQL only. `WWI_SALES_A_02_PersistenceIT` sends it as a native query, with the moment as a
positional parameter:

[source,java]
----
entityManager.createNativeQuery("""
SELECT c.CustomerID, c.CustomerName, h.CreditLimit, c.CreditLimit
FROM Sales.Customers c
         JOIN Sales.Customers FOR SYSTEM_TIME AS OF ?1 h ON h.CustomerID = c.CustomerID
WHERE h.CreditLimit <> c.CreditLimit
ORDER BY c.CustomerID""")
        .setParameter(1, LocalDateTime.of(2015, 1, 1, 0, 0))
        .getResultList()
----

==== WWI_WAREHOUSE_I_04: Incoming and outgoing stock movements

For each stock item with movements in a period, the quantity in, the quantity out as a positive amount, and the net movement, by item name.

[source,sql]
----
DECLARE @from datetime2 = '2016-05-01', @to datetime2 = '2016-06-01';
SELECT si.StockItemID,
       si.StockItemName,
       SUM(CASE WHEN st.Quantity > 0 THEN st.Quantity ELSE 0 END)  AS Incoming,
       SUM(CASE WHEN st.Quantity < 0 THEN -st.Quantity ELSE 0 END) AS Outgoing,
       SUM(st.Quantity)                                             AS NetMovement
FROM Warehouse.StockItemTransactions st
         JOIN Warehouse.StockItems si ON si.StockItemID = st.StockItemID
WHERE st.TransactionOccurredWhen >= @from
  AND st.TransactionOccurredWhen < @to
GROUP BY si.StockItemID, si.StockItemName
ORDER BY si.StockItemName
