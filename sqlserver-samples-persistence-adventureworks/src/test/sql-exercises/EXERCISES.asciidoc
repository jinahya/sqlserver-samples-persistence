= Exercises
:toc: left
:toclevels: 3
:sectanchors:
:source-highlighter: rouge

Exercises for the `AdventureWorks` database: business questions that the analysts of a bicycle maker -- human
resources, marketing, production, purchasing and sales -- would ask, each answered with a query. Every problem is
stated as a request, followed by its solutions. The `sql` blocks are SQL Server's SQL against the installed database
(see link:../../../../README.md[README.md]), and are the ones in `src/test/sql-exercises`, a directory per schema; a parameter is a
T-SQL variable, `@name`, declared with the value the tests use. The `jpaql` blocks are Jakarta Persistence 3.2 query
language against this module's entities. Each exercise has a class of its own in
`src/test/java-exercises`, `aw.<schema>.<ID>_PersistenceIT`; a picked one runs the query, and its Criteria API
counterpart, and checks the rows the SQL returns.

The problems are grouped by the schema whose question they answer, and some of them read the other schemas too. Each
section goes from Basic through Intermediate to Advanced. An id is `AW_<SCHEMA>_<TIER>_<NN>`, numbered within its
schema and tier, and `EXERCISES.yaml` registers every one; an id is never renumbered or reused.

A few things about the mappings shape the JPQL below:

* A foreign key is mapped twice: as an association on the entity, and as a read-only attribute on its mapped
  superclass. Where the column is part of the primary key, the attribute writes it and the association is the
  read-only one. Either can be read in a query: `pv.productId`, or `pv.product`.
* `SalesOrderDetail` references `SpecialOfferProduct` by a composite foreign key, `(SpecialOfferID, ProductID)`. The
  answers reach a sold product as `d.specialOfferProduct.product`, and a special offer as
  `d.specialOfferProduct.specialOffer`.
* Computed columns -- `SalesOrderNumber`, `TotalDue`, `LineTotal`, `OrganizationLevel` -- are read-only attributes, and
  can be selected, compared and summed like any other.
* `hierarchyid` (`OrganizationNode`, `DocumentNode`) is a `byte[]`, and `xml` (`Demographics`) a `String`. Their
  methods, `GetAncestor`, `IsDescendantOf`, `ToString`, `value`, are SQL Server's; the problems which need them, and
  those which need a recursive common table expression, `PIVOT` or a window function, are SQL only. Jakarta
  Persistence sends them as native queries.
* `ProductDocument` is not an entity: its key includes a `hierarchyid`. A problem reading it is SQL only.

== HumanResources

=== Basic

[[AW_HUMANRESOURCES_B_01]]
==== AW_HUMANRESOURCES_B_01: The current employees of each department

HR plans next year's budget. Show how many employees each department has now, the largest first.

[source,sql]
----
SELECT d.Name, d.GroupName, COUNT(h.BusinessEntityID) AS Employees
FROM HumanResources.Department d
         LEFT JOIN HumanResources.EmployeeDepartmentHistory h ON h.DepartmentID = d.DepartmentID AND h.EndDate IS NULL
GROUP BY d.DepartmentID, d.Name, d.GroupName
ORDER BY Employees DESC, d.Name
----

[source,jpaql]
----
SELECT d.name, d.groupName, COUNT(h)
FROM HumanResourcesEmployeeDepartmentHistory h
         JOIN h.department d
WHERE h.endDate IS NULL
GROUP BY d.id_, d.name, d.groupName
ORDER BY COUNT(h) DESC, d.name
----

[[AW_HUMANRESOURCES_I_01]]
==== AW_HUMANRESOURCES_I_01: The ten highest current hourly rates

Payroll reviews the highest pay. Show the ten employees with the highest current hourly rate, the rate of each one's latest change.

[source,sql]
----
SELECT TOP (10) p.FirstName, p.LastName, e.JobTitle, ph.Rate, CAST(ph.RateChangeDate AS date) AS RateChangeDate
FROM HumanResources.EmployeePayHistory ph
         JOIN HumanResources.Employee e ON e.BusinessEntityID = ph.BusinessEntityID
         JOIN Person.Person p ON p.BusinessEntityID = e.BusinessEntityID
WHERE ph.RateChangeDate = (SELECT MAX(ph2.RateChangeDate)
                           FROM HumanResources.EmployeePayHistory ph2
                           WHERE ph2.BusinessEntityID = ph.BusinessEntityID)
ORDER BY ph.Rate DESC, e.BusinessEntityID
;
----

[source,jpaql]
----
SELECT p.firstName, p.lastName, e.jobTitle, ph.rate, ph.rateChangeDate
FROM HumanResourcesEmployeePayHistory ph
         JOIN ph.businessEntity e
         JOIN e.businessEntity p
WHERE ph.rateChangeDate = (SELECT MAX(ph2.rateChangeDate)
                           FROM HumanResourcesEmployeePayHistory ph2
                           WHERE ph2.businessEntityId = ph.businessEntityId)
ORDER BY ph.rate DESC, e.businessEntityId
----

[[AW_HUMANRESOURCES_I_03]]
==== AW_HUMANRESOURCES_I_03: The employees who worked in more than one department

HR looks at internal mobility. Show the employees who have worked in more than one department, with how many departments each one worked in.

[source,sql]
----
SELECT p.FirstName, p.LastName, COUNT(DISTINCT h.DepartmentID) AS Departments
FROM HumanResources.EmployeeDepartmentHistory h
         JOIN Person.Person p ON p.BusinessEntityID = h.BusinessEntityID
GROUP BY h.BusinessEntityID, p.FirstName, p.LastName
HAVING COUNT(DISTINCT h.DepartmentID) > 1
ORDER BY p.LastName, p.FirstName, h.BusinessEntityID

[[AW_HUMANRESOURCES_I_04]]
==== AW_HUMANRESOURCES_I_04: Shift lengths across midnight

HR wants each shift's start, end and length in minutes; a shift that ends at or before its start ends the next day.

[source,sql]
----
SELECT s.ShiftID, s.Name, s.StartTime, s.EndTime,
       DATEDIFF(MINUTE, s.StartTime, s.EndTime) + CASE WHEN s.EndTime <= s.StartTime THEN 1440 ELSE 0 END AS DurationMinutes
FROM HumanResources.Shift s
ORDER BY s.ShiftID
----

[[AW_PRODUCTION_I_03]]
==== AW_PRODUCTION_I_03: The ten products whose work orders finish late the most

The plant manager looks for late production. Show the ten products with the most work orders finished after their due date, and by how many days they were late on average; `ProductID` breaks a tie.
`AVG` of the integer `DATEDIFF` returns would truncate, so it averages a decimal.

[source,sql]
----
SELECT TOP (10) p.ProductID, p.Name, COUNT(*) AS LateWorkOrders, AVG(1.0 * DATEDIFF(DAY, w.DueDate, w.EndDate)) AS AverageDaysLate
FROM Production.WorkOrder w
         JOIN Production.Product p ON p.ProductID = w.ProductID
WHERE w.EndDate > w.DueDate
GROUP BY p.ProductID, p.Name
ORDER BY LateWorkOrders DESC, p.ProductID
----


=== Advanced

[[AW_PRODUCTION_A_01]]
==== AW_PRODUCTION_A_01: The parts of a product, by its bill of materials

Show every part of a product from its bill of materials effective now, down to the raw materials, with the quantity its immediate assembly takes and its depth; a row is effective from its `StartDate` through its `EndDate`, or with no end.

[source,sql]
----
DECLARE @productId int = 818;
DECLARE @asOf datetime = GETDATE();
WITH Parts (AssemblyID, ComponentID, PerAssemblyQty, BomLevel) AS (SELECT b.ProductAssemblyID, b.ComponentID, b.PerAssemblyQty, 1
                                                                   FROM Production.BillOfMaterials b
                                                                   WHERE b.ProductAssemblyID = @productId
                                                                     AND b.StartDate <= @asOf
                                                                     AND (b.EndDate IS NULL OR b.EndDate >= @asOf)
                                                                   UNION ALL
                                                                   SELECT b.ProductAssemblyID, b.ComponentID, b.PerAssemblyQty, p.BomLevel + 1
                                                                   FROM Production.BillOfMaterials b
                                                                            JOIN Parts p ON p.ComponentID = b.ProductAssemblyID
                                                                   WHERE b.StartDate <= @asOf
                                                                     AND (b.EndDate IS NULL OR b.EndDate >= @asOf))
SELECT p.AssemblyID, p.ComponentID, c.Name, p.PerAssemblyQty, p.BomLevel
FROM Parts p
         JOIN Production.Product c ON c.ProductID = p.ComponentID
ORDER BY p.BomLevel, p.AssemblyID, p.ComponentID
----

SQL only: answered with a native query, the SQL above, in `AW_PRODUCTION_A_01_PersistenceIT`.

[[AW_PURCHASING_I_02]]
==== AW_PURCHASING_I_02: The five vendors whose goods were rejected the most

Quality assurance looks for unreliable vendors. Show the five vendors whose received goods were rejected the most, by the share of the quantity received, vendors with nothing received left out; `BusinessEntityID` breaks a tie.

[source,sql]
----
SELECT TOP (5) v.Name,
               SUM(d.ReceivedQty) AS ReceivedQty,
               SUM(d.RejectedQty) AS RejectedQty,
               CAST(SUM(d.RejectedQty) * 100.0 / NULLIF(SUM(d.ReceivedQty), 0) AS decimal(19, 2)) AS RejectedPercent

=== Advanced

[[AW_PURCHASING_A_01]]
==== AW_PURCHASING_A_01: The yearly spend with each vendor, against the year before

The purchasing manager watches how the spend with each vendor moves. Show, for each vendor and year, what was spent on its approved and complete purchase orders, the spend of the vendor's previous year with orders, and the change.

[source,sql]
----
WITH Yearly (VendorID, OrderYear, TotalDue) AS (SELECT h.VendorID, YEAR(h.OrderDate), SUM(h.TotalDue)
                                                FROM Purchasing.PurchaseOrderHeader h
                                                WHERE h.Status IN (2, 4)
                                                GROUP BY h.VendorID, YEAR(h.OrderDate))
SELECT v.Name,
       y.OrderYear,
       y.TotalDue,
       LAG(y.TotalDue) OVER (PARTITION BY y.VendorID ORDER BY y.OrderYear)              AS PreviousTotalDue,
       y.TotalDue - LAG(y.TotalDue) OVER (PARTITION BY y.VendorID ORDER BY y.OrderYear) AS Change
FROM Yearly y
         JOIN Purchasing.Vendor v ON v.BusinessEntityID = y.VendorID
ORDER BY v.Name, y.VendorID, y.OrderYear
----

[[AW_SALES_I_05]]
==== AW_SALES_I_05: The orders and their amounts in each currency

Finance reports sales by currency. Show, for each currency the orders were paid in, how many orders there were, their total in US dollars, and their total in that currency; an order with no rate is in US dollars.

[source,sql]
----
SELECT COALESCE(r.ToCurrencyCode, N'USD')           AS CurrencyCode,
       COUNT(*)                                     AS Orders,
       SUM(h.TotalDue)                              AS TotalDueUsd,
       SUM(h.TotalDue * COALESCE(r.AverageRate, 1)) AS TotalDueInCurrency
FROM Sales.SalesOrderHeader h
         LEFT JOIN Sales.CurrencyRate r ON r.CurrencyRateID = h.CurrencyRateID
GROUP BY COALESCE(r.ToCurrencyCode, N'USD')
ORDER BY Orders DESC, CurrencyCode
----

[[AW_SALES_A_01]]
==== AW_SALES_A_01: The sales of each sales person, a column per fiscal year

The sales director compares the sales persons over the years. Show every sales person's order subtotals for the fiscal years ending in 2022, 2023, 2024 and 2025, a column per year, `0` for a year without sales; Adventure Works' fiscal year starts on the 1st of July.
`SalesPersonID` goes through the pivot, so two sales persons of one last name stay apart; the rows are ordered by the 2025 sales, the most first, then by `SalesPersonID`.

[source,sql]
----
SELECT pvt.SalesPersonID,
       pvt.LastName,
       COALESCE(pvt.[2022], 0) AS [2022],
       COALESCE(pvt.[2023], 0) AS [2023],
       COALESCE(pvt.[2024], 0) AS [2024],
       COALESCE(pvt.[2025], 0) AS [2025]
FROM (SELECT sp.BusinessEntityID AS SalesPersonID, p.LastName, h.SubTotal, YEAR(DATEADD(MONTH, 6, h.OrderDate)) AS FiscalYear
      FROM Sales.SalesPerson sp
               JOIN Person.Person p ON p.BusinessEntityID = sp.BusinessEntityID
               LEFT JOIN Sales.SalesOrderHeader h ON h.SalesPersonID = sp.BusinessEntityID
          AND h.OrderDate >= '20210701'
          AND h.OrderDate < '20250701') AS s
         PIVOT (SUM(s.SubTotal) FOR s.FiscalYear IN ([2022], [2023], [2024], [2025])) AS pvt
ORDER BY COALESCE(pvt.[2025], 0) DESC, pvt.SalesPersonID
----

[[AW_SALES_A_02]]

[source,sql]
----
SELECT t.[Group], t.Name AS Territory, p.LastName, sp.SalesYTD,
       RANK() OVER (PARTITION BY t.[Group] ORDER BY sp.SalesYTD DESC) AS GroupRank

         JOIN Person.Person p ON p.BusinessEntityID = sp.BusinessEntityID
         JOIN Sales.SalesTerritory t ON t.TerritoryID = sp.TerritoryID
ORDER BY t.[Group], GroupRank
;
